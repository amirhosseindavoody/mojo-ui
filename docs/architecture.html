The path from widget to PNG

mojo-ui is a headless software renderer and a small immediate-mode UI in Mojo 1.2. The CPU draws into memory. The demo saves one frame to a PNG and exits. There is no window, event loop, GPU backend, or input handling.

Follow the title first. title.size() asks how much space the text wants. column.place(...) assigns space and moves the stack cursor. title.draw(...) turns the text into colored pixels inside that space.

This is immediate-mode UI. Your calls describe what appears each time you draw. A Stack remembers its current placement cursor while you use it. The library keeps no widget tree between frames. A retained-mode toolkit keeps a tree of widget objects, updates it over time, and can use it to lay out, redraw, and route events.

Public imports

The package entry point re-exports the names you can import from mojo_ui. Follow each import to find the implementing module.

Geometry and clipping

Point, Size, Insets, and Rect use integers. The origin is top left, with x increasing rightward and y increasing downward. Size and Insets clamp negative values to zero.

A Rect is half-open. It includes its left and top edges and excludes its right and bottom edges. The constructor clamps negative dimensions to zero and trims widths or heights whose endpoint would exceed Int.MAX. That keeps right() and bottom() representable even for rectangles far offscreen.

intersection gives you the area two rectangles share, or an empty rectangle when they only touch or are apart. inset shrinks a rectangle by per-edge padding and stops at an empty area when the padding uses up its space. The rasterizer uses intersection to clip and the widgets use inset to make room for padding.

Color and compositing

Color holds straight-alpha 8-bit red, green, blue, and alpha. It defines TRANSPARENT, BLACK, WHITE, RED, GREEN, and BLUE. Color.rgb sets alpha to 255. Color.over blends a source over the destination with wide integer weights and rounds at the end.

Framebuffer and drawing

Framebuffer owns a row-major List[Color]. Pixel (x, y) lives at index y * width + x. Drawing clips to the image bounds before storing pixels. _blend_at reads the current pixel, computes Color.over, and writes the result back.

  • clear replaces every pixel, including alpha. fill_rect blends each pixel of the clipped rectangle.
  • stroke_rect fills four strips inside the rectangle. The strips never overlap, so a corner pixel blends at most once.
  • draw_line draws a one-pixel Bresenham-style line including both endpoints when visible. The code clips the major-axis range before looping, interpolates the minor coordinate in Int128, then checks the minor-axis bounds before each write.
  • fill_rounded_rect tests pixel centers against circular corners. Each sample is either in or out, giving hard, jagged edges at low resolutions.
  • draw_text expands bitmap glyphs at the requested integer scale and clips them. write_png passes the current pixels to _write_png.

Bitmap font

The font is 5 pixels wide and 7 high, with an advance of 6 pixels at scale 1. A glyph fits in SIMD[DType.uint8, 8]. Seven bytes hold the row masks and the eighth is padding. Lowercase maps to uppercase. The table covers uppercase letters, digits, and a few punctuation marks, with a question mark for unsupported characters. text_width excludes the gap after the last glyph.

PNG encoding

The encoder adds a filter type 0 byte to each row and copies the RGBA channels in order. The PNG starts with its signature, then writes IHDR for the image header, IDAT for image data, and IEND to finish.

IDAT wraps the scanlines in zlib using stored (uncompressed) DEFLATE blocks and an Adler-32 checksum. Each PNG chunk also has a bitwise CRC-32 over its type and data. This module writes the format directly without an external image library.

Stack, Label, and Button

Stack.vertical and Stack.horizontal inset the bounds for padding. Each place() call returns a clipped rectangle and advances by the placed size plus any spacing that fits. An empty placement leaves the cursor where it was.

A Label draws one line from the top-left of its bounds. A Button fills a rounded background, insets its padding, and centers and clips its label inside that content area. The button can draw itself. Hit-testing and click handling are future work.

The demo in drawing order

examples/demo.mojo creates a 480 × 248 frame, clears it to a dark color, and draws a rounded panel. Then it places MOJO UI and SOFTWARE RENDERING in a padded column, draws a divider line, and places START and ABOUT side by side. The result goes to examples/out/demo.png.

Look for the divider’s endpoint at divider.right() - 1. A line includes its last point, while a rectangle excludes its right edge, so subtracting one keeps the line inside its layout box.

Tests and Pixi tasks

tests/test_mojo_ui.mojo exercises geometry, blending, rectangles, lines, text, PNG output, and widget layout deterministically without a window. The PNG round-trip test writes a 2 × 2 image, reads the file back, and checks every byte against a reference.

pixi.toml pins the Mojo dependency to 1.2.* and lists Modular’s max channel. From the root, pixi run build precompiles the library to build/mojo_ui.mojoc, pixi run test runs the headless tests, and pixi run example writes the demo PNG.

What would come next

The README starts with a window host using SDL or GLFW through C FFI. The host would present the pixels that the CPU renderer already makes. Pointer and keyboard events would come next. A GPU backend is a possible later step.
